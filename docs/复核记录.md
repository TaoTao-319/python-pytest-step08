# 独立副本复核记录

复核方式是从本地 Git 仓库克隆到独立目录，创建新的虚拟环境，再通过已下载的 wheel 包离线安装 `requirements.txt` 中的依赖。这次验证没有复用原项目虚拟环境，也没有从远程 GitHub 克隆。

## 实际执行步骤

1. 保存项目的本地 Git 提交。
2. 使用 `git clone --no-hardlinks` 创建独立工作副本。
3. 在副本运行 `python -m venv .venv`。
4. 使用 `pip install --no-index --find-links ... -r requirements.txt` 安装依赖。
5. 执行 `python -m pytest -q --junitxml=artifacts/fresh-tests.xml`。
6. 执行 `python demo.py`，检查功能演示结果。

## 结果

独立副本收集并执行 45 个测试场景，全部通过。演示输出如下：

```text
Phone validation: True
Password validation: True
Cart total: 16.50
```

完整命令、依赖安装输出和退出码见 `artifacts/reproduction.txt`。结构化结果和被验证的源码提交见 `artifacts/reproduction.json`。

依赖包来自本地保存的 wheel，离线安装验证了依赖声明可用；没有验证用户的网络连通性或其他操作系统、Python 版本。远程发布完成后，仍可再从实际 GitHub 地址克隆检查。

## 文件保护与命名检查

对原项目的 11 个被复制文件重新计算 SHA-256，与复制前记录全部一致，结果见 `artifacts/source_integrity.json`。说明原文件未被修改。

成果说明和代码注释使用功能主题命名。测试场景标识用输入特点或被验证行为命名。

# 测试设计与覆盖说明

测试对象是手机号校验、密码校验和购物车总价计算。预期结果先按功能规则确定，再与实际输出比较；不直接把函数当前输出当作预期值。

## 功能规则

| 功能 | 有效输入与输出 | 无效输入处理 |
| --- | --- | --- |
| 手机号 | 以 `1` 开头、长度为 11 的 ASCII 数字字符串，返回 `True` | 返回 `False`，不自动去空格、不把整数转换为字符串 |
| 密码 | 长度 8–20，至少一个英文字母和一个 ASCII 数字，返回 `True` | 返回 `False`；允许额外字符与空格，未要求大小写同时存在 |
| 购物车 | 非负有限单价、非负整数数量；先求和，再按 `ROUND_HALF_EVEN` 保留两位小数，返回 `Decimal` | 单价缺失、不可转换、负数、非有限值或数量不合法时抛出 `ValueError` |

购物车输入约定是由商品映射组成的可迭代对象；数量不能使用布尔值。这里的手机号规则是练习规则，不校验真实运营商号段。

## 测试分布

| 测试文件 | 场景数 | 设计方法与关注点 |
| --- | ---: | --- |
| `test_validators.py`：手机号 | 13 | 有效与无效等价类；10/11/12 位长度；ASCII 与全角数字；字符串之外的类型 |
| `test_validators.py`：密码 | 13 | 7/8/20/21 位长度边界；缺字母、缺数字；ASCII 字符规则；允许的特殊字符与空格 |
| `test_cart.py` | 9 | fixture 独立数据；数量变化；空购物车；新增、移除；负单价和负数量 |
| `test_cart_edge_cases.py` | 5 | 缺字段、布尔数量、NaN 单价、零单价 |
| `test_cart_contract.py` | 5 | 半偶舍入、汇总后舍入、生成器输入、调用方数据不被修改 |
| 合计 | 45 | 全部属于默认测试集 |

参数化数据的每一组输入都是独立场景，场景数与测试函数数量不同。逐场景执行状态见 `artifacts/test_cases.csv`。

## 新增场景

| 场景标识 | 输入或操作 | 预期 | 能发现的问题 |
| --- | --- | --- | --- |
| `half_even_round_down` | 单价 `1.005`，数量 1；外部舍入模式设为 `ROUND_DOWN` | `Decimal("1.00")`，指数为 -2 | 小数位数不稳定、向上舍入代替半偶舍入 |
| `half_even_round_up` | 单价 `1.015`，数量 1；外部舍入模式设为 `ROUND_DOWN` | `Decimal("1.02")`，指数为 -2 | 外部 Decimal 舍入设置影响函数结果 |
| `round_after_summing` | 两件单价 `0.005`、数量 1 的商品 | `Decimal("0.01")` | 先把每件商品舍入成零再求和 |
| `test_generator_input_is_supported` | 用生成器提供 `3.25×2` 和 `10.00×1` | `Decimal("16.50")` | 实现错误地依赖列表长度、下标或重复遍历 |
| `test_calculation_does_not_modify_input` | 保存购物车深拷贝，调用函数后比较 | 返回 `16.50`，原数据与深拷贝相等 | 计算过程修改单价、数量或商品顺序 |

## 断言与数据隔离

布尔结果用 `is` 验证；金额使用 `Decimal` 比较；异常用 `pytest.raises(..., match=...)` 验证类型和相关字段。`sample_cart` 使用函数级 fixture，为每个场景创建新的列表与字典。

本项目没有统计代码覆盖率，45 个测试通过不代表全部输入都已覆盖。无效商品容器、超大金额的精度边界和复杂计价规则可作为后续扩展。
